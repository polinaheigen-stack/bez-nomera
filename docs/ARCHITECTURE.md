# Архитектура E27

## От изображения к ответу

1. Вход: JPEG/PNG и рамка `image_id,x,y,w,h` в пикселях исходного изображения. Вырезаем автомобиль, сохраняем пропорции, добавляем поля до квадрата 256×256; bicubic-масштабирование и нормализация ImageNet.
2. Одна DINOv3 ViT-S+/16 и собственная проекция Linear + LayerNorm формируют L2-нормированный вектор 384 чисел. Инференс FP32; без отражений изображения, смешанной точности и дорисовки скрытых деталей. Учитель при поиске не запускается. Ускоритель FP32 использует 4 обработчика подготовки и пакет 32, закреплённую память (pinned memory), 2 CPU-потока PyTorch. Вычисления TF32 выключены. Одиночный запрос поддерживается тем же extractor.
3. Векторы галереи уточняются по четырём ближайшим соседям с долей смешивания 0,25. Первые 50 кандидатов пересортируются методом k-reciprocal (взаимные ближайшие соседи), `k1=5`, `lambda=0.6`.
4. P2 проверяет поддержку кандидата тремя его соседями в галерее. При `alpha=0.5` итоговая оценка `clip(base_score × (1 − alpha + alpha × support), 0, 1)`. Порог **0.713592811641558** фиксирован по отдельной калибровке. P2 меняет принятие, а не порядок top-10.
5. Первый кандидат принят, если оценка не ниже порога; иначе отказ. Top-10 сохраняется в обоих случаях. Оценка сходства не является вероятностью правильного ответа.

Каждый запрос независим от остальных запросов. Галерея не пополняется запросами. Имя файла, идентификатор камеры, время, география и эталонные ответы не являются признаками модели. Госномер не распознаётся. На вход нужны рамки; автоматический детектор и сегментатор не входят в E27.

## Обучение и выбор версии

Это веса проверенного стенда 5: обучение 20 эпох, выбран checkpoint эпохи 14 по отдельной выборке разработки. Во время обучения использовались метки идентичности и отношения между чистыми тренировочными векторами собственного учителя E25. Учитель и его веса не нужны для инференса. Состав данных, настройки, лицензия и код приведены в [training/README.md](../training/README.md).

Рецепт постобработки выбран на данных разработки; порог — на калибровке 73/612. Контроль 77/324 использован после фиксации. Он исторический, поэтому не заменяет независимый скрытый тест.

## Реализация и состояние

Backend: Python, PyTorch, timm, NumPy, FastAPI. Frontend: React, TypeScript, Vite. Точные версии закреплены в файлах зависимостей. SHA-256 модели и конфигураций проверяется при загрузке; несовместимый пакет отклоняется. Один сервис обслуживает веб и программный интерфейс, каждый запуск имеет `run_id`.

При смене устройства галерею нужно переиндексировать. При перезапуске сервиса галереи и история очищаются; скачанные файлы остаются у пользователя. API предназначен для локальной или защищённой сети.

## API

- `GET /api/v1/status`, `GET /api/v1/settings` — состояние.
- `PUT /api/v1/settings/device`, JSON `{"device":"cuda"}` или `{"device":"cpu"}` — устройство.
- `POST /api/v1/galleries` — multipart `name`, `csv`, несколько `images`.
- `GET /api/v1/galleries/{id}` — ход индексации.
- `POST /api/v1/runs` — multipart `gallery_id`, `csv`, несколько `images`.
- `GET /api/v1/runs/{id}` — ход поиска и выдача.
- `POST /api/v1/runs/{id}/evaluation` — multipart `ground_truth`, только для оценки после поиска.
- `GET /api/v1/runs/{id}/evaluation`, `/evaluation/report`, `/export`, `/evidence` — оценка и результаты.
- `POST /api/v1/runs/{id}/cancel` — отмена.

Машиночитаемое описание — `/openapi.json`. Приём видеопотока, трекинг и отправка исходящих уведомлений в E27 не реализованы.

## Выходные файлы

- `submission.csv`: без заголовка, ID запроса и 10 различных ID галереи, порядок входного query CSV.
- `candidates.csv`: `query_id,gallery_id,confidence`; максимум один принятый кандидат на запрос. При отказе строки нет.
- `embeddings.npy`: float32, `(Q+G,384)`, сначала запросы, затем галерея в CSV-порядке. Это исходные векторы до постобработки.
- JSON порядка, рецепта, версий и контрольных сумм — дополнительные доказательства, не замена трём файлам оценщика.
